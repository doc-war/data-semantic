        Why Not Another I18N Framework
        
不是更好的 i18n 框架，
是一次范式转变

        
以国际化为例：传统框架靠命令式代码把数据一条条塞进 DOM，字段越多、胶水代码越多。
          data-semantic 把绑定关系写进 HTML 本身，新增字段不需要碰一行 JS。

      


      

        

          
⚠ 每个字段都要手写一行更新逻辑，10 个字段 = 10 行胶水代码

          

            
i18next命令式 · UI 与更新逻辑耦合

            
<div id="hello"></div>
<div id="desc"></div>

// 每个 DOM 节点都要手动更新
function renderUI(lang) {
  i18next.changeLanguage(lang);
  document.getElementById('hello')
    .textContent = i18next.t('hello');
  document.getElementById('desc')
    .textContent = i18next.t('desc');
  // 有多少字段，就要写多少行……
}

          

        

        

          
✓ 新增字段只需在 HTML 加一个属性，JS 零改动

          

            
data-semantic声明式 · UI 与数据解耦

            
<div data-semantic="hello"></div>
<div data-semantic="desc"></div>

// 一次调用，自动批量渲染全部绑定
const locales = {

        The Protocol
        
协议规范

        
协议只定义三种正交声明机制：data-semantic 绑定 textContent，
          data-semantic-display 绑定 Element.style.display，
          data-semantic-<attr> 绑定同名 DOM 属性，且 <attr> 必须落在白名单内。
          事件处理器、style、内联脚本一律不允许被渲染。

      


      

        

          
            
属性绑定 DOM用途示例

          
          
            
data-semantictextContent基础文本内容data-semantic="user.name"

            
data-semantic-displaystyle.display显示 / 隐藏控制<h1 data-semantic-display="user.isVip">

            
data-semantic-placeholderplaceholder输入框占位符<input data-semantic-placeholder="…">

            
data-semantic-valuevalue表单初始值（单向）<input data-semantic-value="…">

            
data-semantic-titletitle鼠标悬停提示<button data-semantic-title="…">

            
data-semantic-altalt图片替代文本<img data-semantic-alt="…">

            
data-semantic-srcsrc动态资源链接<img/video/iframe data-semantic-src="…">

            
data-semantic-hrefhref动态跳转地址<a data-semantic-href="…">

            
data-semantic-aria-labelaria-label无障碍标签<button data-semantic-aria-label="…">

            
data-semantic-aria-descriptionaria-description无障碍详细描述<div role="tooltip" …>

            
data-semantic-contentcontentmeta 动态内容<meta data-semantic-content="…">

            
data-semantic-data-*data-*（透传）自定义 data 属性data-semantic-data-user-id="…"

          
        

      


      

        
KEY PATH key 路径遵循标准 JSON 寻址（点分隔），业务字段名禁止包含 .，否则无法被路径解析命中。

        
ARRAY 数组必须整体传入，不支持增量合并；绑定槽位必须是标量叶子值，绑定到对象/数组会跳过渲染并告警。

        
SCOPE 运行时只负责已有结构的数据同步，不负责生成 DOM；数组收缩时多余节点自动清空但不删除。

        
DISPLAY data-semantic-display 是 style 的唯一特例：布尔值控制显示/隐藏（true→显示、false→none），字符串值原样透传（如 flex、grid）。

        
SECURITY 事件处理器、style、全局标识符、iframe 等内联脚本类目标一律不在白名单内，任意 data-semantic-style 均被拒绝。

      

    

  


  


  
  

    

      

        AI-Native Advantages
        
为什么这对 AI 生成代码更友好

        
相比命令式框架的强耦合，data-semantic 把「结构」和「数据」两个关注点彻底分离，三方各自独立演进。

      

      

        

          
          
UI 复杂度低

          
AI 只需生成带语义声明的纯 HTML 结构——这正是它的强项。新增字段只需加一个 data-semantic 属性，无需编写任何绑定代码。

        

        

          
          
协作解耦

          
设计端、前端、后端可并行工作，互不阻塞。

          
    
            
  • 数据侧（i18n 文件 / API）可独立增删字段，不影响 UI
    • 
            
  • UI 侧（HTML 模板）可自由改布局，不担心破坏绑定
    • 
          

        

        

          
          
测试成本趋近于零

          
UI 与数据可双端独立单测，几乎不需要集成测试。

          
    
            
  • UI 侧：原生 HTML，直接验证视觉与响应式布局
    • 
            
  • 数据侧：纯 JSON，Node.js 环境独立测试
    • 
            
  • 集成层：只有 render() 一座桥，逻辑简单到几乎无需测试
    • 
          

        

        

          
          
保留语义

          
渲染后 data-semantic 属性原样保留，页面结构自始至终携带数据语义，供三方平台精准分析。

          
    
            
  • 结构即语义：data-semantic="page.title" 永久声明「此处是页面标题」
    • 
            
  • 协议声明：加载时自动注入 <meta name="data-semantic" content="1.0">
    • 
          

        

      

    

  


  


  
  

    

      

        Rendering Model
        
细粒度增量渲染

        
运行时以「槽位索引 + 细粒度增量渲染」为核心，首次渲染建立索引，此后每次调用只更新真正变化的槽位。

      


      

        

          

            
01 / 槽位索引

            
建立 key → 元素索引

            
首次 render() 扫描作用域内全部绑定，缓存 key 到元素列表的映射，后续渲染不再全量扫描 DOM。

          

          

            
02 / 细粒度渲染

            
只更新变化的槽位

            
对数据做纯增量深合并，仅收集本次传入的叶子路径并更新对应槽位；未涉及的槽位保持原值，互不干扰。

          

          

            
03 / 结构自愈

            
MutationObserver 兜底

            
监听结构与 data-semantic* 属性变化，增量重建索引，把已有数据自动补渲染到新插入的节点。

          

          

            
04 / 流式友好

            
为 AI 流式输出而生

            
数据可小块高频注入，每次渲染只更新注入字段对应的槽位；删除字段用显式 undefined 表达。
