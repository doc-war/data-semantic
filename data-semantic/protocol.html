01 / Declaration

声明方式

协议支持 12 种 data-semantic-* 属性绑定，覆盖文本内容、显示控制、表单值、媒体资源、无障碍标签等场景。所有绑定属性均在白名单内，不在白名单内的属性一律忽略。

属性绑定一览
属性绑定 DOM用途示例
data-semantictextContent基础文本内容<p data-semantic="user.name">
data-semantic-displaystyle.display显示 / 隐藏控制<h1 data-semantic-display="user.isVip">
data-semantic-placeholderplaceholder输入框占位符<input data-semantic-placeholder="…">
data-semantic-valuevalue表单初始值（单向）<input data-semantic-value="…">
data-semantic-titletitle鼠标悬停提示<button data-semantic-title="…">
data-semantic-altalt图片替代文本<img data-semantic-alt="…">
data-semantic-srcsrc动态资源链接<img/video/iframe data-semantic-src="…">
data-semantic-hrefhref动态跳转地址<a data-semantic-href="…">
data-semantic-aria-labelaria-label无障碍标签<button data-semantic-aria-label="…">
data-semantic-aria-descriptionaria-description无障碍详细描述<div role="tooltip" …>
data-semantic-contentcontentmeta 动态内容<meta data-semantic-content="…">
data-semantic-data-*data-*（透传）自定义 data 属性data-semantic-data-user-id="…"
  • WHITELIST 仅白名单内的 12 种 data-semantic-* 属性会被 runtime 处理，其余自定义 data 属性一律忽略。
  • SECURITY 事件处理器（onclick 等）、style、全局标识符、iframe src 等内联脚本类目标均不在白名单内，任意 data-semantic-style / data-semantic-onclick 均被忽略。
02 / Display Binding

display 绑定

data-semantic-display 是唯一绑定到 style 的属性，用于控制元素的显示与隐藏。它拥有一套独立的布尔渲染逻辑。

渲染规则
数据值渲染行为说明
true显示元素移除 display:none
falsestyle.display = "none"隐藏元素
"" / 0 / null / undefined / "false"style.display = "none"所有逻辑假值均视为隐藏
其他真值字符串显示元素如 "flex"、"grid"，值原样透传到 style.display
 
<!-- 布尔控制 -->
<h1 data-semantic-display="user.isVip">VIP 用户</h1>

<!-- 字符串值原样透传到 style.display -->
<div data-semantic-display="layout.mode">内容区域</div>
// layout.mode = "flex"  → style.display = "flex"
// layout.mode = true    → 显示
// layout.mode = false   → style.display = "none"
NO CSS data-semantic-display 只写入 style.display，不读取、不修改 CSS class。显示/隐藏逻辑与 CSS 层叠完全解耦。
FALSE "false"（字符串）与 false（布尔）效果完全一致，均输出 style.display = "none"。
03 / Addressing

寻址方式

UI 侧声明的槽位值，对应数据侧的 key 路径。槽位命名遵循标准 JSON 寻址（点分隔），支持嵌套与数组索引。

绝对寻址

使用点分隔路径直接定位数据对象中的任意深度字段。

<p data-semantic="page.title"></p>
<p data-semantic="user.addresses.0.city"></p>
NAMING key 路径遵循标准 JSON 寻址（点分隔），业务字段名禁止包含 .，否则无法被路径解析命中。
相对寻址

当元素处于某个作用域容器内时，可省略前缀，使用相对路径绑定。

<!-- 在作用域容器内，省略前缀 -->
<div data-semantic-scope="user">
  <p data-semantic="name"></p>   <!-- 等价于 user.name -->
  <p data-semantic="title"></p>  <!-- 等价于 user.title -->
</div>
RESTRICT 相对寻址仅在声明了 data-semantic-scope 的容器内生效，且仅向下穿透一层作用域。
方括号寻址

数组元素必须使用数字索引的方括号语法进行寻址。

<div data-semantic="pages.list[0].name"></div>
<div data-semantic="pages.list[2].title"></div>
NUMERIC 方括号内的索引必须是数字，不支持字符串键或负数索引。
纯点号声明

对于嵌套路径，可以使用纯点号分隔的声明方式。

<p data-semantic="user.profile.displayName"></p>
<img data-semantic-src="assets.heroImage" />
04 / List Container

list 容器

runtime 通过 data-semantic-list 标记列表容器，支持基础列表、嵌套列表与翻译模式。

基础列表

声明列表容器与列表项模板，runtime 根据数组长度自动渲染列表项。

<ul data-semantic-list="nav.items">
  <li>
    <a data-semantic-href=".url">
      <span data-semantic=".label"></span>
    </a>
  </li>
</ul>
嵌套列表

列表容器内可包含子列表，形成树状结构。子列表的作用域自动继承父级数组元素。

<ul data-semantic-list="tree.nodes">
  <li>
    <span data-semantic="name"></span>
    <ul data-semantic-list="children">
      <li>
        <span data-semantic="name"></span>
      </li>
    </ul>
  </li>
</ul>
翻译模式

在翻译场景中，列表的渲染采用差异化策略：叶子节点使用增量更新，容器节点使用全量替换。

  • 叶子增量：列表项内的叶子节点（文本、属性）使用增量更新，未变化的字段保持原值。
  • 容器全量：列表容器（data-semantic-list）在数组长度变化时执行全量替换，确保 DOM 结构与数据一致。
// 翻译场景：语言切换时，列表容器整体替换，叶子节点增量更新
const zh = { nav: { items: [
  { label: "首页", url: "/" },
  { label: "关于", url: "/about" }
]}};
const en = { nav: { items: [
  { label: "Home", url: "/" },
  { label: "About", url: "/about" }
]}};

DataSemantic.render(zh);
DataSemantic.render(en); // 列表项增量更新 label，容器结构不变
05 / Data Boundary

数据边界

render() 对传入数据有严格约束，开发者与 runtime 必须共同遵守。

render() 必须传入纯 JSON 对象

render(data) 的参数必须是合法的纯 JSON 对象，不接受函数、DOM 节点、Date 等非 JSON 值。

// ✅ 合法：纯 JSON 对象
DataSemantic.render({ page: { title: "欢迎" } });

// ❌ 非法：根数组
DataSemantic.render([{ title: "欢迎" }]); // 根数组禁止，必须包裹在对象内
ROOT ARRAY 根级别数组（如 render([])）被明确禁止。数组必须作为对象的属性值传入。
数组必须整体传入

数组使用全量替换语义，不支持 undefined 占位的部分更新。每次传入数组必须包含完整数据。

// ✅ 数组必须整体传入（deepMerge 不递归合并数组）
DataSemantic.render({ pages: { list: ['a', 'b'] } });

// ❌ 用 undefined 占位更新数组元素，会被整体替换
DataSemantic.render({ pages: { list: [undefined, 'x'] } }); // 整个 list 被替换
key 必须是标量

绑定目标必须是叶子节点（标量值：字符串、数字、布尔），不接受绑定对象或数组本身。

<div data-semantic="pages.list.0.name"></div>  // ✅ 标量叶子
<div data-semantic="pages.list"></div>          // ❌ 绑定对象/数组，跳过渲染并告警
06 / Security

安全约束

runtime 对所有属性写入实行严格的白名单机制，杜绝 XSS 与注入风险。

属性白名单

只有 data-semantic-* 白名单内的 12 种属性会被 runtime 读取和写入，其余自定义属性一律忽略。

// 白名单属性（仅限以下 12 种）
data-semantic           → textContent
data-semantic-display   → style.display
data-semantic-placeholder → placeholder
data-semantic-value     → value
data-semantic-title     → title
data-semantic-alt       → alt
data-semantic-src       → src
data-semantic-href      → href
data-semantic-aria-label       → aria-label
data-semantic-aria-description → aria-description
data-semantic-content   → content
data-semantic-data-*    → data-*（透传）
禁止项列表

以下属性或行为被明确禁止，runtime 会拒绝执行：

  • 事件处理器：onclick、onerror 等所有 on-* 属性一律不在白名单内。
  • style 属性：除 data-semantic-display 绑定的 style.display 外，禁止直接操作 style。
  • 全局标识符：禁止引用 window、document 等全局对象。
  • script / eval：禁止任何脚本注入或动态执行。
  • 非白名单属性：data-semantic-style、data-semantic-onclick 等均被拒绝。
iframe src URL 校验

当通过 data-semantic-src 写入 <iframe> 时，URL 必须通过白名单协议校验。

// ✅ 仅允许以下协议
https://example.com         // HTTPS 协议
http://example.com          // HTTP 协议
//example.com               // 协议相对 URL

// ❌ 以下协议被拒绝
javascript:alert(1)         // 危险！被拦截
data:text/html,...          // 危险！被拦截
URL 仅允许 https://、http://、///（协议相对 URL）三种前缀，其余一律拒绝写入。
07 / Protocol Meta

协议 meta

runtime 加载时自动向页面 <head> 注入 meta 标签，向第三方平台声明本页面遵循 data-semantic 协议。

自动注入

runtime 初始化完成后，会在 <head> 中自动注入以下 meta 标签：

<!-- runtime 加载时自动注入到 <head> -->
<meta name="data-semantic" content="1.0" />

<!-- 三方平台可通过此 meta 标签识别页面是否遵循 data-semantic 协议 -->
<!-- content 值为协议版本号，遵循 semver 规范 -->
AUTO meta 标签由 runtime 自动注入，业务方无需手动添加。重复声明不会产生冲突，runtime 会去重。
08 / Compiler

编译器

编译器（ds-compile）用于构建阶段的代码优化，遵循「保留语义、移除数据」的核心原则。

保留语义属性 + --remove-data-attrs

编译器保留所有 data-semantic-* 语义属性，仅移除非语义的 data 属性（通过 --remove-data-attrs 选项）。

// 编译前
<div data-semantic="page.title" data-foo="bar"></div>

// 编译后（--remove-data-attrs）
<div data-semantic="page.title"></div>  <!-- 语义属性保留，非语义 data 属性移除 -->
check() 校验规则

编译器内置 check() 校验函数，在编译阶段检查协议合规性：

  • 白名单校验：检查所有 data-semantic-* 属性是否在白名单内。
  • 寻址合法性：校验 key 路径是否包含非法字符，是否使用了数字索引。
  • 绑定目标：检查绑定目标是否为叶子节点（非对象/数组）。
  • iframe URL：校验 data-semantic-src 在 iframe 上的 URL 协议。
编译是数据求值，不是语义擦除

编译器的核心定位是数据求值——将静态 HTML 中的语义声明编译为可直接运行的代码，而非擦除语义标记。

  • 编译 ≠ 擦除：data-semantic 属性在编译后完整保留，页面结构自始至终携带数据语义。
  • 编译 = 求值：编译器将声明式属性转换为高效的 runtime 调用代码，减少运行时解析开销。
  • 产出物：编译产物是包含完整语义属性的 HTML + 优化后的 JS 运行时调用，可供三方平台精准分析。
